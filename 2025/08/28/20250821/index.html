最近測試了兩個 Python 工具：uv 虛擬環境管理和 Authlib 套件實現第三方登入。

Authlib

快速實現第三方登入的套件，目前測試了常用的 Google、GitHub 都可以快速搭配使用，LINE 需要小修改。Facebook 沒測試是因為註冊驗證比較嚴格，申請太久就跳過了。

OAuth 2.0 流程 (Google 舉例)

三個主要角色：使用者、Google、自身後端服務

  1. 使用者點擊登入 - 使用者在網站點擊「用 Google 登入」
  2. 跳轉到 Google - 後端服務將使用者轉向到 Google 授權
  3. 使用者同意授權 - 使用者在 Google 頁面確認授權，同意存取基本資料
  4. Google 回傳授權碼 - Google 將使用者重定向回網站，並帶上一個 code
  5. 後端換取 Token - 後端服務用 code 向 Google 換取 access_token
  6. 取得使用者資料 - 後端服務用 access_token 向 Google API 取得使用者資料

整個過程中，後端服務永遠不會接觸到使用者的 Google 帳號密碼。
如想更深入理解 OAuth 2.0 流程，可先用 Python + requests 手動實作第三方登入，並不搭配任何套件，會很有感。

不使用 Authlib 的話

過去在不使用相關套件下，每個步驟都要很清楚實作細節，要實現上述 OAuth 流程，需要處理大量程式碼：

  • 手動組裝授權 URL 參數
  • 解析回調參數和錯誤處理
  • 實作 token 交換的 HTTP 請求
  • 管理 token 過期和刷新機制
  • 防範 CSRF 攻擊和 state 參數驗證

Authlib 已經把常用的第三方服務（Google、GitHub、X等）都包裝好了，可以快速整合使用，省去很多重複的底層實作。

uv 套件與虛擬環境管理

uv 用 Rust 重寫，速度快很多，使用體驗感覺像是 Node.js 開發那樣透過 npm 管理相關依賴，在專案中直接管理依賴，讓開發環境更乾淨、可重現。

可解決的痛點

  • 跨平台差異：Windows 上習慣用 Anaconda，Linux 上常用 venv，導致使用體驗不一致。
  • 環境混亂：臨時測試常常懶得重建虛擬環境，導致一個環境裝了很多不相關的套件，久而久之很難管理
  • VSCode 能自動偵測：使用 uv，專案資料夾中的 .venv 會被 VSCode 自動識別，無需手動切換解釋器。
    結論：每個專案自帶獨立環境，安裝速度快，未來開發更傾向使用 uv。
