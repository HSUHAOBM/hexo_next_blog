問題二：找不到執行檔（MSBuild 案例）

對於 .NET Framework 的建置，需使用 MSBuild.exe 。這裡遇到的是：平常在本機可以使用的指令（如 MSBuild），在 GitLab Runner 中找不到。

原因解析：
Windows 環境變數有三個層級：

  • Machine：系統層級，對所有使用者和服務有效
  • User：使用者層級，只對目前登入的使用者有效
  • Process：程序層級，只對目前的程式有效

GitLab Runner 以 Windows 服務運行，只能存取 Machine 層級 的環境變數。

檢查方法：

下一階段：嘗試 CD 部署方案

目前 CI 建置已經搞定，接下來要試著處理 CD 的部分。

之前在 Linux 環境處理 .NET Core 或 Python 專案時，都能用 SSH + Docker 搞定。但 .NET Framework 的部署情境會比較複雜一些。

經過查資料，目前朝向這幾個作法去嘗試：

環境配置：

  • A：Linux GitLab（主控端）
  • B：Windows Runner（建置機）
  • C：Windows Server（目標部署機）

可能的部署方案：

  1. B 編譯 → 複製到 C：在 B 機建置完成後，用 robocopy 或 WebDeploy 推送到 C 機
  2. C 自己拉程式 → C 上建置：C 機裝 GitLab Runner，直接 git clone 最新程式後在本機建置
  3. B 編譯 → SSH 到 C 執行部署：B 機建置完成，透過 SSH 連到 C 機執行部署腳本

不確定實務都用哪種做法，所以應該都會試試看。
